# 求解算法：讨论草案

日期：2026-09-16。状态：讨论草案，**未实现、未做实验**。依据主文档第 12 节（第三版定义）。

本文给出推荐路线和理由，不承诺求解速度，也不承诺全局最优。

---

## 1. 问题结构：先看哪些性质可以利用

| 性质 | 来源 | 对算法的意义 |
|---|---|---|
| 所有直管沿坐标轴，设备 90° 一档旋转 | 12.2、12.3 | 几何全部轴对齐；坐标可取整数毫米；碰撞可用轴对齐盒快速筛查 |
| 占地是外接矩形，净距和检修区都是盒 | 12.5、12.6 | 设备摆放就是经典的**矩形布局问题**，有成熟的精确建模方法 |
| 管路是正交路径，弯头、最小直段、高度变化都是“沿路径累计”的量 | 12.3、12.4 | 管路搜索可以把这些量放进搜索状态，边走边检查 |
| 设备位置决定管长；管道占空间又影响设备怎么摆 | 目标函数 | 两者**耦合**，不能各求一次就结束 |

难点主要在第四行。第一次讨论就提到过：若按顺序逐根布管，A 占了通道后，B 可能无路可走。算法必须能回头修改已经布好的管，也能回头移动设备。

---

## 2. 推荐路线：摆放—布管—反馈 三层循环

    ┌──────────────────────────────────────────────┐
    │ 第 1 层  设备摆放（CP-SAT 约束规划）            │
    │   变量：设备/模块位置、旋转                     │
    │   目标：面积 + 管长估计 + 通道预留              │
    └───────────────┬──────────────────────────────┘
                    ↓ 固定设备位置
    ┌──────────────────────────────────────────────┐
    │ 第 2 层  管路布线（协商式拥堵布线 + A*）         │
    │   所有管先允许重叠，逐轮提高冲突代价，直到无冲突 │
    └───────────────┬──────────────────────────────┘
                    ↓ 布线结果 / 拥堵位置
    ┌──────────────────────────────────────────────┐
    │ 第 3 层  反馈与局部重排（大邻域搜索）            │
    │   在拥堵处放开几台设备重新摆放，再布线           │
    │   保留历史最好的可行解                          │
    └───────────────┬──────────────────────────────┘
                    ↓ 每个候选解
    ┌──────────────────────────────────────────────┐
    │ 独立校验器：用精确几何检查全部硬规则、计算 J     │
    └──────────────────────────────────────────────┘

---

## 3. 第 1 层：设备摆放

**推荐工具：** Google OR-Tools 的 CP-SAT 求解器。开源（Apache 2.0），Python 可直接调用。

**为什么适合：**

1. 坐标取整数毫米后，本问题的摆放部分几乎全部可以精确表达：
   - 不重叠：CP-SAT 自带二维不重叠约束 `AddNoOverlap2D`。设备盒按净距膨胀，检修区作为附加盒。
   - 旋转 4 选 1：每种朝向一组可选盒，只激活一组。
   - 外接矩形：x_min、x_max 等为变量，每个盒都在其内。
   - 面积 W·H：CP-SAT 支持整数乘积约束。
   - 长宽比：线性约束。
   - 锁定、区域、对齐、顺序、等间距、对称：都是线性约束。约束注册草案中模板的 `linear_form` 能力正好对接这里。
2. 能给出下界。小规模时可以证明摆放子问题最优；大规模时至少知道离最优还差多少。

**管长在这一层只能估计：** 真实管长要布线后才知道。用端口间曼哈顿距离作估计，再加上“通道预留”：给每条连接在设备之间预留一定宽度的空间，避免设备挤得太紧，导致管道无处可走。预留宽度由第 3 层根据拥堵情况调整。

**这一层的局限：** 最优的只是“估计代价下的摆放”，不是整体最优。

## 4. 第 2 层：管路布线

### 4.1 单根管：A* 搜索

**搜索空间：** 不用均匀网格，而用**非均匀轨道线**。候选坐标来自：设备盒按净距膨胀后的边界、端口坐标、已布管道两侧按净距偏移后的位置。它比均匀网格小得多，轴对齐的最短路径通常就走在这些线上。

**搜索状态**不仅是位置，还包括：

| 状态分量 | 用途 |
|---|---|
| 当前方向 | 转弯时计入一个弯头 |
| 当前高度、已发生的高度变化次数 | 计算 N_layer；超过 K 时立即剪枝（硬上限） |
| 距上一个管件已走的直管长度 | 保证转弯前满足 ρ + ρ + ℓ_min 等直段要求 |
| 是否仍在端口接入段 | 接入段不计高度变化 |

**单根管代价：** w_L·长度/L₀ + w_B·弯头/B₀ + w_C·高度变化/C₀，与目标函数一致。

### 4.2 多根管：协商式拥堵布线（PathFinder）

这是 FPGA 芯片布线的成熟方法，专门解决“先布的管挡住后布的管”：

1. 第一轮：每根管单独找最优路径，**允许**管道之间重叠。
2. 统计每处空间被几根管占用。
3. 下一轮重新布所有管，经过拥堵处要多付代价：
   - 当前拥堵代价：本轮有多少根管在抢。
   - 历史拥堵代价：该处过去一直拥堵，代价持续累积。
4. 重复，直到没有重叠。

效果：真正需要走窄通道的管会留下，有别的路可走的管会被逐渐挤到别处。它不依赖布管顺序，这正是第一次讨论中提出的要求。

### 4.3 三通

拓扑 JSON 已经给出三通连接哪几条管。做法：

1. 先布三通的主路。
2. 支路从支路端口出发做 A* 搜索，终点是“主路上任意一个合法的三通安装位置”。合法指三通实体放得下，两侧直管满足最小长度。
3. 找到后在该处插入三通，主路随之分成两段。
4. 两入口可交换（4.6 节）：两种分配都试，取代价低的一种。

### 4.4 自动变径

口径已由输入确定，变径段是派生构件。A* 在端口附近展开时，把变径段长度计入“必须先走的直管长度”即可。

## 5. 第 3 层：反馈与局部重排

单独两层都不能保证整体好。第 3 层用**大邻域搜索**把两层连起来：

1. 从当前最好解出发，选一小块区域：拥堵最严重处、管长最长的连接附近，或随机选取。
2. 放开这块区域内的几台设备，其余设备固定，交给 CP-SAT 重新摆放。这个子问题规模小，求得快。
3. 只重布受影响的管。
4. 用校验器计算真实 J；更好就接受，否则按一定概率接受或丢弃。
5. 把布线拥堵信息反馈给第 1 层：在拥堵处加大通道预留。
6. 时间用完时输出历史最好的可行解。

这就是主文档第 8 节讨论的“临时分块”：分块只是求解手段，每次都可以放开，不会永久锁死原问题。

---

## 6. 独立校验器

求解过程中为了速度会做近似，例如用盒代替真实实体、用轨道线代替连续空间。所以每个候选解最后都要交给校验器：

- 用精确几何检查：真实弯头圆弧、变径段、斜三通内部斜段、净距、检修区。
- 逐条计算注册规则的残差，给出 hard 规则是否全部满足。
- 计算真实的 A、L、N_bend、N_layer 和 J。

校验器与算法无关，以后换算法也不用改。它就是约束注册草案中的“内核统一处理规则”部分。

---

## 7. 能保证什么、不能保证什么

| 结果 | 能否给出 |
|---|---|
| 满足全部硬规则的可行解 | 找到时能，并附校验报告 |
| 随时间持续改进，可随时停止并输出当前最好解 | 能 |
| 摆放子问题的下界、小规模下的最优证明 | 能（CP-SAT） |
| 整体全局最优证明 | **不能**。布线与摆放是分层近似 |
| 超时没找到解 | 只能报告“未找到”，不能说“无解” |

如果需要评估离最优还差多少：对很小的算例，另写一个精确的整体模型（网格上的多商品流 + 摆放），求出真正最优，与本方案的结果对比。这一模型只用于测试，规模一大就无法求解。

## 8. 约束注册机制如何接入

| 模板能力 | 用在哪一层 |
|---|---|
| `linear_form` | 第 1 层 CP-SAT 直接编码（对齐、顺序、区域、长宽比等） |
| `partial` | 第 2 层 A* 剪枝（高度变化上限等） |
| `bounds` | 第 1 层缩小坐标范围 |
| `depends_on` | 第 3 层选择放开哪些设备 |
| 只有残差函数 | 校验器检查；第 3 层作为罚分参与比较 |

新增规则时，至少提供残差函数就能被正确检查；补充上述能力后，求解会更快。

## 10. 按实际规模调整（2026-09-16）

用户给出：**约 560 台设备、200 条连接；可接受求解时间十几分钟。**

以下是按规模推理的调整，**没有经过实测**，时间分配只是初始设想。

### 10.1 规模带来的判断

1. **不能整体一次交给 CP-SAT。** 560 个盒的二维不重叠 + 面积乘积，在十几分钟内一般只能拿到可行解，难以收敛到好解，也无法证明最优。CP-SAT 改为只求解局部子问题（每次几十台设备）。
2. **至少 160 台设备不在任何连接上。** 200 条两端连接最多涉及 400 台设备（三通可能使涉及的设备更少）。这些设备只影响占地和碰撞，可以在布管主体完成后填入空位，或作为独立的装箱子问题处理。
3. **200 根管的协商布线可行，但单根 A* 必须快。** 每轮协商要重布大量管，通常需要几十轮。纯 Python 实现的 A* 很可能不够快，布线核心需要编译型实现（例如 Rust、C++，或用 Numba 加速的 Python）。
4. **大邻域搜索的迭代次数有限。** 十几分钟内大约只能完成几十次“局部重排 + 重布线”，所以初始布局的质量非常关键。

### 10.2 调整后的流程

    ① 预处理（秒级）
       - 标准模块合并为一个刚性块，内部管道作为障碍物
       - 按连接关系把设备聚类（同一系统、同一连接链的设备归为一簇）
    ② 初始摆放（1–2 分钟）
       - 簇内：CP-SAT 小规模摆放，得到每簇的紧凑布局
       - 簇间：把每簇当作一个大盒，再用 CP-SAT 摆放
       - 无连接设备：暂不摆放，留到 ⑤
    ③ 两级布线（3–5 分钟）
       - 全局布线：粗网格（例如 200–500 mm 一格）上用协商布线确定每根管的大致走廊
       - 详细布线：在分到的走廊内用非均匀轨道线 A* 得到精确路径、弯头、三通位置
    ④ 大邻域搜索（剩余时间的大部分）
       - 在拥堵处或管长最长处放开一两个簇，重新摆放并只重布受影响的管
       - 每次改进后运行校验器；保存历史最好可行解
    ⑤ 无连接设备填空（1 分钟内）
       - 在当前外接矩形内优先填空位；放不下时再扩边
    ⑥ 最终校验与报告

注意：“簇”是临时分块，第 ④ 步可以打散重组，不会永久锁定设备相对位置（主文档第 8 节）。

### 10.3 面积项的处理

560 个盒时直接用 W·H 乘积会明显拖慢 CP-SAT。建议：

- 子问题中使用 W + H，或固定宽度只最小化长度；多试几个宽度。
- 校验器仍按真实 W·H 计算 J 并比较方案，目标定义不变，只是求解中间过程用了替代量。

### 10.4 需要继续确认

1. 560 台设备中，有多少属于重复的标准模块？模块越多，实际要摆放的块越少。
2. 无连接的设备是什么类型，例如配电柜、备用设备？摆放时是否有特殊要求？
3. 十几分钟是必须严格停止的上限，还是希望大约在这个时间出结果？
4. 实现语言：布线核心是否接受 Rust / C++，还是希望全部使用 Python？

### 10.5 用户补充与更正（2026-09-16）

1. **复制组：** 冷水主机 + 冷冻水泵 + 冷却水泵组成制冷链模块，共 4 组，完全复制；多台冷却塔组成冷却塔组。实际摆放单元远少于 560。
2. **更正 10.1 第 2 条：** 所有设备都有连管，不存在无连接设备。“200 条连接”应理解为包含三通分支的管网连接，每条可涉及多台设备。流程 ⑤“无连接设备填空”取消。
3. **时间：** 不设硬上限。求解器应能持续运行、随时输出当前最好解。
4. **实现语言：** 可接受 Rust；用户更希望尽量采用解析解。可行性分析见《解析求解-可行性与矩阵形式.md》：骨架固定后的占地有 max-plus 矩阵闭式解，管长为线性规划；骨架本身只能搜索。据此，摆放层改为“序列对骨架搜索 + max-plus 解析压紧 + LP 精修”，CP-SAT 作为可选的子问题求解器。
