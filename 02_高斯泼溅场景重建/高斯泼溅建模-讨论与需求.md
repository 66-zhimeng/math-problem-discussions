# 高斯泼溅场景重建：讨论与需求

整理日期：2026-09-16。本文为对话摘要，非逐字转录；记录需求与候选思路，不代表已验证实现。

## 1. 用户希望实现的结果

1. 对一个物体或房间拍摄多角度视频。
2. 从视频重建可自由切换视角的三维场景。
3. 房间内桌椅等家具可以单独选择、移动和旋转。
4. 场景中可放入角色；角色不能穿过墙体、地面和家具。
5. 尽量使用现有开源工具，支持本地处理，先讨论小原型路径。

用户随后明确要求先不动手制作原型，继续讨论网格与技术路径。尚无实现、训练或性能测试。

## 2. 已讨论的技术区分

1. 高斯泼溅主要提供场景外观，不自动提供可交互物体划分或可靠的实体碰撞边界。
2. 移动家具需要将其表示为独立对象；独立高斯对象或独立网格均属于候选表示，并未最终选定。
3. 角色碰撞需要单独的几何表示，例如简化墙面、地板及家具碰撞体，不必逐个高斯做碰撞。
4. 家具移开后，原先被遮挡的墙面、地面和家具背面可能缺失，需要补拍或补全；不能声称仅凭不可见区域就能准确恢复真实形状。
5. 网格可通过多视角重建流程生成，但通常还需修补；显示网格与简化碰撞体可分开管理。

## 3. 候选流程，尚未定案

1. 拍摄有充分视角覆盖的视频，提取清晰帧。
2. 估计相机位姿，进行场景外观与必要几何重建。
3. 区分静态房间与可移动家具，形成独立资产。
4. 补全移开家具后暴露的区域，清理原位置残留的外观。
5. 为墙体、地面、家具建立适当精度的碰撞几何。
6. 在查看器或引擎中统一坐标、尺度与对象变换，实现选择、移动、旋转和角色运动。

房间高斯外观加独立家具网格是一种候选组合，不是已经确定必须采用的架构。家具移动时，其显示表示和碰撞体必须同步变换。

## 4. 本地硬件条件

用户提供两台机器：

1. RTX 3060 Ti，8 GB 显存。
2. RTX 5060 Ti，16 GB 显存。

此前讨论倾向用 16 GB 机器进行主要重建实验、8 GB 机器进行较小场景测试。这只是初步分工，尚未核实具体工具对显卡架构与软件环境的支持，也未测量可处理场景规模、速度或显存占用。

## 5. 待继续讨论

1. 最终更看重逼真外观，还是可编辑网格与家具交互？
2. 可移动家具采用高斯、网格还是混合表示？
3. 拍摄时能否移开家具，单独补拍房间和家具？
4. 对象划分、几何修补可接受多少人工操作？
5. 目标运行平台、场景规模与交互性能要求。
6. 开源工具链的实际许可、显卡支持和端到端可用性需另行核验。

## 6. 与自动排布方向的关系

两者是本项目中的两个主题。当前没有要求把扫描场景作为自动布管输入，也没有要求把两个功能整合成同一软件；未来如需结合，另行定义接口和需求。
